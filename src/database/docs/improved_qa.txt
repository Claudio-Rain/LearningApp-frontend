What is asynchrony?	<p>A programming model where work runs separately from the primary application thread. When the work completes, it notifies the main thread.</p><p><strong>Benefits:</strong></p><ul><li>Improved performance and responsiveness</li><li>Applications don't freeze while waiting for I/O or computationally expensive operations</li></ul>
Why do we need asynchronous programming?	<p>Asynchronous programming prevents applications from becoming unresponsive during long-running operations. It enables:</p><ol><li>Network requests, database queries, and file I/O to run in the background</li><li>Time-consuming computations without blocking the UI</li><li>Better resource utilization by allowing other work while waiting for I/O</li><li>Enhanced user experience through a responsive interface</li></ol>
What syntax defines an asynchronous method in C#?	<p>An asynchronous method must have:</p><ol><li>The <code>async</code> modifier in the method signature</li><li>At least one <code>await</code> expression in the body</li><li>One of these return types: <code>void</code>, <code>Task</code>, <code>Task&lt;T&gt;</code>, or <code>ValueTask&lt;T&gt;</code></li></ol><p><strong>Note:</strong> Asynchronous methods cannot have <code>out</code> or <code>ref</code> parameters, but can take any number of regular parameters.</p>
How does the Task.WhenAll method work?	<p><code>Task.WhenAll</code> returns a new task that completes when all passed tasks complete. All tasks run in parallel, and the await suspends execution until all tasks finish.</p><p><strong>Example:</strong></p><pre><code class="language-csharp">await Task.WhenAll(new[] { t1, t2, t3 })</code></pre><p>This is useful for coordinating multiple independent asynchronous operations.</p>
How does the Task.WhenAny method work?	<p><code>Task.WhenAny</code> returns a new task that completes when at least one of the passed tasks completes. Use it for race scenarios—get whichever result completes first.</p><p><strong>Example:</strong> Querying multiple servers and using the fastest response. The completed task can be accessed via the returned task's <code>Result</code> property.</p>
Can I access a variable declared in a try block from within the finally block?	<p>It depends on scope. Variables declared inside the try block are <strong>not accessible</strong> in finally.</p><p><strong>Solution:</strong> Declare variables outside the try block instead.</p><p><strong>Warning:</strong> If a variable is initialized inside try and an exception occurs before initialization, finally cannot access it safely.</p>
What is a CancellationToken?	<p>A <code>CancellationToken</code> is a cooperative cancellation mechanism for gracefully stopping long-running tasks.</p><p><strong>Key components:</strong></p><ul><li><code>CancellationTokenSource</code> — creates tokens and signals cancellation</li><li><code>CancellationToken</code> — passed to tasks to check if cancellation was requested</li></ul><p><strong>Usage:</strong> Create a CancellationTokenSource, pass its token to tasks, and call <code>Cancel()</code> to request graceful shutdown. Unlike forced termination, tokens allow tasks to clean up resources before stopping.</p>
What is Serialization?	<p>Serialization is the process of converting an in-memory object into a stream of bytes or text (e.g., JSON, XML, binary format).</p><p><strong>Essential for:</strong></p><ul><li>Storage (saving to disk or database)</li><li>Transmission (sending over networks)</li></ul>
What is Deserialization?	<p>Deserialization is the reverse of serialization: converting bytes or text back into an in-memory object.</p><p><strong>Together with serialization, it enables:</strong></p><ul><li>Saving state</li><li>Communicating between systems</li><li>Persisting data across sessions</li></ul>
